Residual stream

The idea that holds a transformer together: one vector per token, which every layer reads from and adds to.

Residual connections

A plain network replaces its input at every layer. A residual connection adds the layer's output to its input instead:

\[ \text{plain: } x_{l+1} = f_l(x_l) \qquad\qquad \text{residual: } x_{l+1} = x_l + f_l(x_l) \]

The layer only has to learn a change to its input (the “residual”), not the whole output. If a layer has nothing useful to add, it can output roughly zero and the input passes through untouched. From ResNet (He et al., 2015), which used it to train 152-layer image networks.

Why they make depth trainable

Differentiate one residual layer, \(x_{l+1} = x_l + f(x_l)\):

\[ \frac{\partial x_{l+1}}{\partial x_l} = I + \frac{\partial f}{\partial x_l} \qquad\Longrightarrow\qquad \frac{\partial L}{\partial x_l} = \frac{\partial L}{\partial x_{l+1}} + \frac{\partial L}{\partial x_{l+1}} \frac{\partial f}{\partial x_l} \]

The first term is the gradient from above, copied through unchanged. That's the “a value used twice: add the gradients” rule: \(x_l\) is used by \(f\) and by the addition.

Going back through many layers, a plain network multiplies one Jacobian per layer, so the gradient shrinks or blows up exponentially with depth. With residuals, there's always a direct path from the loss to every layer with no multiplications at all: expand the product and one of its terms is just \(\partial L / \partial x_L\):

\[ \frac{\partial L}{\partial x_0} = \frac{\partial L}{\partial x_L} \prod_{l=0}^{L-1} \left( I + \frac{\partial f_l}{\partial x_l} \right) = \frac{\partial L}{\partial x_L} \Bigl( I + \text{(terms through one or more layers)} \Bigr) \]

(For row vectors, the factors multiply in order from the top layer down.)

The residual stream

In a transformer, the running vector \(x\) for each token is called the residual stream. It starts as the token's embedding and runs through the whole model. No layer replaces it: each one reads from it (through a LayerNorm and its own input projection) and writes to it (by adding its output projection's result).

Since every layer adds, the final stream is a sum:

\[ x_{\text{final}} = x_0 + \sum_{\text{every attention and MLP layer}} \text{(that layer's output)} \]

So the stream works like a shared memory or communication channel of width \(C\): early layers write information into it, later layers read it back out. Different layers tend to use different directions (subspaces) of it, so they don't overwrite each other.

SublayerJob
AttentionMoves information between positions: reads from other tokens' streams and writes into this one.
MLPProcesses each position on its own: widen to \(4C\), non-linearity (GELU), narrow back to \(C\). Much of the model's stored knowledge is thought to live here.

The transformer block

\[ \begin{aligned} x &\leftarrow x + \operatorname{Attention}\bigl(\operatorname{LN}_1(x)\bigr) \\ x &\leftarrow x + \operatorname{MLP}\bigl(\operatorname{LN}_2(x)\bigr) \end{aligned} \qquad\qquad \operatorname{MLP}(h) = \operatorname{GELU}(h W_1 + b_1)\, W_2 + b_2 \]

\(W_1\) is \(C \times 4C\) and \(W_2\) is \(4C \times C\). Every block has the same shape; a model is \(N\) of them stacked, each with its own weights.

Pre-norm vs post-norm

FormulaNotes
Post-norm (2017 original)\(x \leftarrow \operatorname{LN}\bigl(x + f(x)\bigr)\)The norm sits on the stream, so every gradient passes through every LayerNorm. Deep stacks needed careful learning-rate warmup to train at all.
Pre-norm (GPT-2 onwards)\(x \leftarrow x + f\bigl(\operatorname{LN}(x)\bigr)\)The norm is only on the branch. The stream is never normalised, so the identity path from the loss to every layer stays clean.

Because a pre-norm stream is never normalised, it grows as layers add to it. That's why pre-norm models need a final LayerNorm before the output layer.

The whole model

\[ \begin{aligned} x_0 &= \text{tok\_emb}[\text{tokens}] + \text{pos\_emb}[0..T{-}1] && (B, T, C) \\ x &\leftarrow \operatorname{Block}_l(x), \quad l = 1, \dots, N && (B, T, C) \\ \text{logits} &= \operatorname{LN}_f(x)\; W_U && (B, T, V) \end{aligned} \]

\(W_U\) (the “unembedding”, or lm_head) maps the stream back to a score per vocabulary token. GPT-2 ties it to the token embedding, \(W_U = W_E^\top\), since reading a token into the stream and scoring the stream against tokens are closely related jobs. With RoPE, there's no pos_emb: position goes into attention instead (see Positions).

Keeping the scale in check

Every sublayer adds to the stream, and there are \(2N\) of them. If each adds something of similar size and roughly independent, the stream's variance grows like the number of additions. GPT-2 counters this at initialisation by scaling down the weights of each sublayer's output projection (attention's \(W_O\), the MLP's \(W_2\)):

\[ \text{std} = \frac{0.02}{\sqrt{2N}} \qquad (\text{instead of } 0.02) \]

That also means each block starts close to the identity (\(f(x) \approx 0\)), so a freshly initialised deep model behaves like a shallow one and training can grow it from there.

Reading the stream

Because the stream is a sum and the output is (after the final LayerNorm) a linear map of it, you can look inside a model by treating partial sums as if they were the final stream:

  • Logit lens: apply \(\operatorname{LN}_f\) and \(W_U\) to the stream after layer \(l\) to see what the model would predict if it stopped there. Predictions typically sharpen layer by layer.
  • Direct logit attribution: push one layer's output through \(W_U\) on its own to see which tokens that layer pushes up or down.
  • Features as directions: concepts tend to be represented as directions in the stream, which layers write and later layers read. Linear probes and sparse autoencoders look for them.

These are approximations (the final LayerNorm isn't quite linear), but they work well enough to be the starting point for most interpretability work.
