Attention

The part of a transformer that moves information between positions.

What it does

Each position in the sequence builds its output as a weighted average of information from other positions. The weights depend on content: how well what this position is looking for matches what each other position contains. Each position produces three vectors from its own embedding:

VectorRole
Query \(q\)What am I looking for?
Key \(k\)What do I contain? (What queries should match me?)
Value \(v\)What do I pass on to whoever attends to me?

Attention itself has no notion of order: shuffle the positions and each output just moves with its input. Position comes from elsewhere, such as learned position embeddings or RoPE.

Attention moves information between positions; the MLP that follows it in each block processes each position on its own.

Scaled dot-product attention

\[ \operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left( \frac{QK^\top}{\sqrt{d}} + M \right) V \]

One head, \(T\) positions, head size \(d\). Softmax is over each row.

StepFormulaShape
Scores\(S = QK^\top / \sqrt{d}\)   (\(S_{tj} = q_t \cdot k_j / \sqrt{d}\))\(T \times T\)
Mask\(S + M\), with \(M_{tj} = -\infty\) where \(t\) may not see \(j\), else 0\(T \times T\)
Weights\(A = \operatorname{softmax}(S + M)\), each row sums to 1\(T \times T\)
Output\(O = AV\)   (\(o_t = \sum_j A_{tj}\, v_j\))\(T \times d\)

Why divide by √d

If the entries of \(q\) and \(k\) are independent with mean 0 and variance 1, then

\[ \operatorname{Var}(q \cdot k) = \operatorname{Var}\left(\sum_{i=1}^{d} q_i k_i\right) = \sum_{i=1}^{d} \operatorname{Var}(q_i k_i) = d \]

so dot products grow with the head size. Large scores push the softmax towards one-hot, where its gradients are nearly zero. Dividing by \(\sqrt{d}\) brings the variance back to 1.

The causal mask

A language model is trained to predict token \(t + 1\) at position \(t\). If position \(t\) could see later positions, it could just copy the answer. So position \(t\) may only attend to positions \(j \le t\):

\[ M_{tj} = \begin{cases} 0 & j \le t \\ -\infty & j \gt t \end{cases} \]

The diagonal is always allowed, so every row has at least one finite score, and the softmax never sees a row of all \(-\infty\).

Fewer queries than keys (a KV cache, where new queries attend to cached keys): with \(T_q\) queries and \(T_k\) keys, query \(i\) sits at position \(T_k - T_q + i\), so it may see keys \(j \le i + (T_k - T_q)\). In PyTorch: torch.ones(Tq, Tk, dtype=torch.bool).tril(diagonal=Tk - Tq). When \(T_q = T_k\), that's the usual mask.

Multi-head attention

Rather than one attention over the full model width \(C\), split it into \(H\) heads of size \(d = C / H\), run attention in each independently, and concatenate. Each head can learn a different pattern, such as “the previous token” or “the matching bracket”. The total cost is the same as one big head.

\[ \begin{aligned} Q,\, K,\, V &= XW_Q,\; XW_K,\; XW_V && W_Q, W_K, W_V: C \times C \text{ (often one } C \times 3C \text{ matrix)} \\ \text{head}_h &= \operatorname{Attention}(Q_h, K_h, V_h) && Q_h = \text{columns } [hd, (h+1)d) \text{ of } Q \\ \operatorname{MultiHead}(X) &= \operatorname{Concat}(\text{head}_1, \dots, \text{head}_H)\, W_O && W_O: C \times C \end{aligned} \]
StepShapePyTorch
Input\((B, T, C)\)
Project, split q/k/v\(3 \times (B, T, C)\)self.qkv(x).split(C, dim=-1)
Split heads\((B, H, T, d)\)q.view(B, T, H, d).transpose(1, 2)
Attention per head\((B, H, T, d)\)attention(q, k, v)
Merge heads\((B, T, C)\)out.transpose(1, 2).reshape(B, T, C)
Output projection\((B, T, C)\)self.proj(out)

transpose makes the tensor non-contiguous, so merging needs reshape (or .contiguous().view(...)), not plain view.

Backward pass

For one head, given \(\partial L / \partial O\). Forward was \(S = QK^\top/\sqrt{d}\) (masked), \(A = \operatorname{softmax}(S)\), \(O = AV\). Every step reuses a rule from the Layers page.

\[ \begin{aligned} \frac{\partial L}{\partial V} &= A^\top \frac{\partial L}{\partial O} \qquad\qquad \frac{\partial L}{\partial A} = \frac{\partial L}{\partial O}\, V^\top \\[6pt] \frac{\partial L}{\partial S} &= A \odot \left( \frac{\partial L}{\partial A} - \operatorname{rowsum}\!\left( \frac{\partial L}{\partial A} \odot A \right) \right) \\[6pt] \frac{\partial L}{\partial Q} &= \frac{1}{\sqrt{d}}\, \frac{\partial L}{\partial S}\, K \qquad\qquad \frac{\partial L}{\partial K} = \frac{1}{\sqrt{d}} \left(\frac{\partial L}{\partial S}\right)^{\!\top} Q \end{aligned} \]
LineWhere it comes from
\(V\) and \(A\)Matrix product \(O = AV\): \(\partial A = \partial O\, V^\top\), \(\partial V = A^\top \partial O\).
\(S\)Softmax backward, row by row. The rowsum is a \(T \times 1\) column, broadcast across each row.
\(Q\) and \(K\)Matrix product \(S = Q K^\top / \sqrt{d}\), treating \(K^\top\) as the weight: \(\partial Q = \partial S\, K / \sqrt{d}\), and \(\partial K = (\partial S)^\top Q / \sqrt{d}\) from \(\partial (K^\top) = Q^\top \partial S / \sqrt{d}\), transposed.

Masked positions have \(A_{tj} = 0\), so \(\partial L / \partial S_{tj} = 0\) there too: no gradient flows through a connection that wasn't used, without any special handling. Cache: \(Q\), \(K\), \(V\) and \(A\).

For multi-head attention, the reshapes and transposes just move gradients back to where their values came from, and the projections are ordinary linear layers.

Cost

WhatPer head
Compute\(O(T^2 d)\): two \(T \times T\)-sized matrix products
Memory\(O(T^2)\) for the scores and weights

The \(T^2\) is why context length is expensive. Fused kernels like FlashAttention (behind F.scaled_dot_product_attention) compute the same result in tiles, without ever storing the full \(T \times T\) matrix. During generation, a KV cache stores past keys and values so each new token costs \(O(Td)\) rather than recomputing everything.
